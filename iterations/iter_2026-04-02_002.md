## Immutable Architectural Rules (from original spec)

### Core Rule

> **Logic computes → Phaser renders**
>
> - `battle/` never imports Phaser
> - Phaser scenes contain no game rules

### Integration Pattern (required for all new features)

```
Input (player click / enemy action)
  → pass to battle function
  → receive new BattleState
  → emit STATE_CHANGED
  → Phaser updates visuals based on new state
```

### Cell-based System (fundamental field rule)

- **Cell is the base unit** of the system, not the unit/character
- An attack selects a cell or set of cells
- An effect is applied to a unit if it **occupies** that cell
- Front row is checked through cells: if at least one front-row cell is occupied by a living unit → row is alive

### Attack — always a sequence of steps (mandatory order)

1. Determine target cells
2. Validate them against attack rules
3. Find units in those cells
4. Deduplicate (one unit = one effect)
5. Apply effect

### Allowed Unit Shapes

`1x1`, `1x2` (1 row 2 cols), `2x1` (2 rows 1 col), `2x2` — defined in `shapes.ts` as `SHAPES`

## Key Data Structures

### BattleState (types.ts)

```ts
interface BattleState {
  units: Map<string, Unit>; // all units
  occupancy: OccupancyMap; // cell↔unit bidirectional map
  roundQueue: string[]; // turn queue; [0] = currently acting unit
  phase: "select_target" | "end";
  validTargets: CellCoord[];
}
```

### Unit (types.ts)

```ts
interface Unit {
  id: string;
  name: string;
  hp: number;
  maxHp: number;
  initiative: number;
  shape: UnitShape; // offsets: [{dr, dc}]
  anchor: CellCoord; // { side, row, col }
  actionType: 'attack' | 'heal';
}
```

### CellCoord

```ts
type Side = "player" | "enemy";
type Row = 0 | 1; // 0 = front (closest to enemy), 1 = back
type Col = 0 | 1 | 2;
```

## Grid Orientation (IMPORTANT)

```
[Player Back (row=1)] [Player Front (row=0)] | [Enemy Front (row=0)] [Enemy Back (row=1)]
         col 0=bottom, col 1=mid, col 2=top
```

- **row** → horizontal strip: for player, front (row=0) is RIGHTMOST; for enemy, LEFTMOST
- **col** → vertical position within strip: 0=bottom, 2=top
- Pixel position formula: `cellPixelPos(side, row, col)` in `Game.ts`
- Canvas fills the full browser window; grid is vertically centered with `LAYOUT_SCALE * 40` offset for the initiative bar

## Turn Flow (Game.ts)

```
create()
  → seedUnits()
  → buildRoundQueue()            ← initiative.ts
  → startActiveUnitTurn(state)

startActiveUnitTurn(state):
  activeUnit = units.get(roundQueue[0])
  if player:
    validTargets = activeUnit.actionType === 'heal'
      ? getFriendlyTargets(side, occupancy)     ← targeting.ts
      : getMeleeTargets(side, occupancy)        ← targeting.ts
    phase='select_target', emit STATE_CHANGED, wait for click
  if enemy:   700ms delay → enemyTurn()

onCellClick(coord):
  → handleTargetSelect(coord, state)
      if activeUnit.actionType === 'heal':
        → resolveHeal([coord], HEAL_AMOUNT, state)  ← combat.ts
        → 500ms delay → advanceQueue → startActiveUnitTurn
      else:
        → resolveAttack([coord], DAMAGE, state)     ← combat.ts
        → checkGameOver(next)
        → 500ms delay → advanceQueue → startActiveUnitTurn

advanceQueue(state):
  remaining = roundQueue.slice(1)
  remaining = pruneQueue(remaining, units)      // remove dead units
  queue = remaining.length > 0 ? remaining : buildRoundQueue(units)  // new round
```

## Combat Rules

1. **Melee targets**: if enemy front row is alive → front row only; else → back row
2. **Deduplication**: if a unit occupies multiple target cells — effect applied once
3. **Initiative**: sorted descending; ties → interleave player first, then enemy
4. **Round**: each unit acts once; after the last one — queue rebuilds
5. **Dead units**: removed from queue via pruneQueue() after each attack

### Healer Rules

6. **Heal targets**: all occupied cells on the healer's own side (no row restriction)
7. **Heal effect**: `hp = Math.min(maxHp, hp + HEAL_AMOUNT)` — cannot overheal
8. **No game-over check** after heal — healing cannot end the battle
9. **Enemy healer AI**: automatically picks the ally with the lowest `hp / maxHp` ratio

## Resolution & Display Quality (added in iter 002)

### Problem (iter 001)

The game canvas was fixed at **900×500 px** with `Scale.FIT`, causing Phaser to CSS-upscale it to fill the browser window. On a 2K monitor (2560×1440) the scale factor was ~2.84×, producing blurry/blocky output. Additionally, `devicePixelRatio` was ignored, meaning each CSS pixel was not backed by physical monitor pixels.

### Solution

A single `LAYOUT_SCALE` constant drives all layout and font sizes across the entire codebase. No separate resolution-vs-layout split: one number scales everything coherently.

```
LAYOUT_SCALE = Math.min(window.innerWidth / 900, window.innerHeight / 500)
```

On 2560×1440 → `LAYOUT_SCALE ≈ 2.84`
On 1920×1080 → `LAYOUT_SCALE ≈ 2.13`
On 1280×720  → `LAYOUT_SCALE ≈ 1.42`
On 900×500   → `LAYOUT_SCALE = 1.0`  (original baseline)

### Changes Made

#### `src/core/Constants.ts`
```ts
export const LAYOUT_SCALE = Math.min(window.innerWidth / 900, window.innerHeight / 500);
export const CELL_SIZE  = Math.round(80 * LAYOUT_SCALE);
export const CELL_GAP   = Math.round(6  * LAYOUT_SCALE);
export const SIDE_GAP   = Math.round(80 * LAYOUT_SCALE);
// GRID_COLS, GRID_ROWS, DAMAGE — unchanged
export const HEAL_AMOUNT = 10;
// COLORS.validHeal = 0x44dd44  ← green highlight for heal targets
```

#### `src/config.ts`
```ts
width:      window.innerWidth,
height:     window.innerHeight,
resolution: window.devicePixelRatio,   // Phaser allocates canvas at DPR× physical pixels
scale: {
  mode:       Phaser.Scale.NONE,       // no CSS upscaling
  autoCenter: Phaser.Scale.NO_CENTER,
}
```
Canvas occupies the full window at native resolution. `resolution: devicePixelRatio` makes Phaser's internal draw buffer match the physical pixel count of the screen.

#### `src/objects/InitiativeBar.ts`
All local sizing constants (`CARD_W`, `CARD_H`, `CARD_GAP`, `DIVIDER_GAP`, `ACTIVE_LIFT`) and all font sizes (`10px`, `11px`) are now computed via `LAYOUT_SCALE`.

#### `src/scenes/Game.ts`
All hardcoded pixel offsets (`+40` grid Y, `-14` label gap, `-18` side-label gap, `y=8` bar Y, `-20` status Y) and font sizes (`11px`, `14px`) scaled via `LAYOUT_SCALE`.

#### `src/objects/UnitView.ts`
Unit padding, text offsets, HP bar height (`barH`), bar margin, and `strokeThickness` all scaled via `LAYOUT_SCALE`. `barH` stored as a class field so the `update()` method uses the same computed value instead of a hardcoded `6`.

#### `src/objects/CellView.ts`
Border thickness: `Math.max(2, Math.round(2 * LAYOUT_SCALE))` — scales up proportionally while staying at least 2 px.

### Rule: All pixel constants must go through LAYOUT_SCALE

Any future hardcoded size, offset, or font size **must** be expressed as `Math.round(N * LAYOUT_SCALE)`. Do **not** add raw pixel numbers to rendering code.

### Pixel Art Sprites

`pixelArt: true` is kept. Sprites are rendered via `setDisplaySize(w, h)` where `w` and `h` are already `LAYOUT_SCALE`-aware (derived from `CELL_SIZE`). At large scales the sprites appear proportionally larger but remain crisp because Phaser uses `image-rendering: pixelated` for upscaling — this is intentional and correct for pixel art.

## Immutable Architectural Rules

### Core Rule

> **Logic computes → Phaser renders**

- `battle/` never imports Phaser
- Phaser scenes contain no game rules

## Integration Pattern (required for all new features)

```text
Input (player click / enemy action)
→ pass to battle function
→ receive new BattleState
→ emit STATE_CHANGED
→ Phaser updates visuals based on new state
```

## Cell-based System (fundamental field rule)

- **Cell is the base unit of the system**, not the unit/character
- An attack selects a cell or set of cells
- An effect is applied to a unit if it occupies that cell
- Front row is checked through cells: if at least one front-row cell is occupied by a living unit → row is alive

## Attack — always a sequence of steps (mandatory order)

1. Determine target cells
2. Validate them against attack rules
3. Find units in those cells
4. Deduplicate *(one unit = one effect)*
5. Apply effect

## Allowed Unit Shapes

`1x1`, `1x2` *(1 row 2 cols)*, `2x1` *(2 rows 1 col)*, `2x2`  
— defined in `shapes.ts` as `SHAPES`

## Templates vs. Instances

- `UnitBlueprint` — static data template (in `src/data/unitDefinitions.ts`): defines name, stats, shape, rowTrait, race
- `Unit` — live battlefield instance created from a blueprint: has `id`, `anchor`, current `hp`
- A single blueprint can produce multiple instances *(e.g. two orcs of the same type on the field)*
- Bench stores blueprints; the field stores Unit instances

### CellCoord

```ts

type Row = 0 | 1;   // 0 = front, 1 = back

```

## Grid Orientation (IMPORTANT)

```text
[Player Back (row=1)] [Player Front (row=0)] || [Enemy Front (row=0)] [Enemy Back (row=1)]
col 0=bottom, col 1=mid, col 2=top
```

- **row** → horizontal strip: player front (row=0) is RIGHTMOST; enemy front LEFTMOST
- **col** → vertical position: 0=bottom, 2=top
- Pixel position formula: `cellPixelPos(side, row, col)` in `Game.ts`

## Game Flow

### Phase 1 — Placement (`phase: 'placement'`)

```text
create()
  → initBattle()
      autoPlacePlayer(state)    ← starting lineup → field; rest → benchUnits
      autoPlaceEnemies(state)   ← random race, fill front row then back row
  → buildUnitViews()
  → enterPlacementPhase()
      buildBenchPanel()         ← cards left of player grid
      buildStartBattleButton()  ← «В бой» below initiative bar
```

### Player interactions

| Action | Result |
|------|--------|
| Click bench card | Select it |
| Click empty player cell (bench selected) | Place unit |
| Click occupied player cell (bench selected) | Swap bench↔field |
| Click player field unit (nothing selected) | Select it |
| Click another field unit (field unit selected) | Swap if shapes fit |
| Click empty cell (field unit selected) | Move unit there |
| Double-click player field unit | Return to bench |
| Click «В бой» | Start battle |

Enemy cells are not interactive during placement.

### Auto-Placement Algorithms (`autoPlace.ts`)

**Player — `autoPlacePlayer()`:**

1. Split `PLAYER_STARTING_IDS` by `rowTrait`
2. Front units → iterate cols 0→2, place at first free `(row=0, col)` via `canPlace`
3. Back units → iterate cols 0→2, place at first free `(row=1, col)` via `canPlace`
4. Remaining → `state.benchUnits`



---

### Enemies — `autoPlaceEnemies()`

1. Pick random race
2. Front row: for each col 0→2, pick random from `frontPool`, `canPlace` → `placeUnit`
3. Back row: for each still-free col, pick random from `backPool`, `canPlace` → `placeUnit`

---

### Phase 2 — Battle (`phase: 'select_target'`)

```text
startBattle()
  → destroy bench panel + button
  → buildRoundQueue() → startActiveUnitTurn(state)

startActiveUnitTurn:
  player → validTargets, phase='select_target', wait for click
  enemy  → 700ms delay → enemyTurn()

onCellClick → handleTargetSelect
  heal   → resolveHeal() → 500ms → advanceQueue → startActiveUnitTurn
  attack → resolveAttack() → checkGameOver()
         → 500ms → advanceQueue → startActiveUnitTurn

advanceQueue: slice(1) → pruneQueue → rebuild if empty
```

## Combat Rules

1. **Melee targets**: front row if alive, else back row
2. **Deduplication**: multi-cell unit hit once per attack
3. **Initiative**: descending; ties → player before enemy
4. **Round**: each unit acts once; queue rebuilds after last
5. **Dead units**: removed via `pruneQueue()` after each attack
6. **Heal targets**: all occupied cells on healer's own side
7. **Heal**: `hp = Math.min(maxHp, hp + HEAL_AMOUNT)` — no overheal
8. **Enemy healer AI**: targets ally with lowest `hp/maxHp` ratio

## Resolution & Display (from iter 002)

```ts
LAYOUT_SCALE = Math.min(window.innerWidth / 900, window.innerHeight / 500)
```

- All pixel values: `Math.round(N * LAYOUT_SCALE)` — no raw numbers in rendering code
- Canvas: native resolution, `resolution: window.devicePixelRatio`, `Scale.NONE`
- New units use colored rectangles (no `textureKey` → UnitView fallback rect)

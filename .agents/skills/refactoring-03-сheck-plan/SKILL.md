You receive a plan. Based on the previous analysis of the game code and your previous implementation/refactoring plan check the plan and write conclusions.

Check:

- Check if it's up to the task and does what it's supposed to do.
- Do you see any major risks in it that aren't covered in the plan for the next stages?
- Carefully check that plan meets the requirements of @CLAUDE.md file and does not violate the boundaries.

Dont's:

- Don't mention minor comments fixes.
- Don't add comments "to clarify" a comment; only write things that are critical to the architecture.

Arter checking the plan:

- Write your proposals for this particular stage, if you have any. Divide proposals into 2 parts: proposal to code, proposal to comments. NO PROPOSALS for further stages in this block.

Then write the conclusion — can the plan be implemented now or it needs fixing.

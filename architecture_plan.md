Добавлено обнаружение непокрытых top-level слоёв: чистая функция `findUncoveredLayers()` (`scripts/layer-coverage.mjs`) сравнивает директории, реально существующие в `src/` (`readdirSync`), со списком `RULES.map(r => r.root)` и с `LAYER_COVERAGE_EXCLUSIONS` (сейчас пуст — все текущие top-level директории покрыты правилами); exclusion без непустого `reason` не подавляет ошибку. Оба модуля покрыты фокусированными тестами: `tests/scripts/boundaryPolicy.test.ts`, `tests/scripts/layerCoverage.test.ts`. **Важное ограничение, которое покрытие НЕ доказывает:** layer coverage гарантирует только *наличие* правила для каждой директории — она не проверяет, что существующие blocklist-правила образуют полную и взаимоисключающую матрицу зависимостей. Если позже появится, например, `save/`, у которого будет свой rule (coverage удовлетворено), ничто не заставит blocklist других существующих layers (`battle`, `campaign` и т.д.) добавить `'save'` в свой `banned` — они могут начать молча импортировать `save/`, и проверка останется зелёной. `world/**` не подвержен этому конкретно благодаря allowlist-модели; остальные layers — да. Единственный application seam — `applyBattleLifecyclePhaseAction({ source, state, action })` в `phaseHandlers/battlePhaseHandler.ts`: он вызывает чистое `applyBattleLifecycleAction`, и только при сигнале `persistPlayerPlacements` (переименован из `persistCampaignPlacements`) резолвит хранилище через `PlayerSessionStore`. `PhaseManager` больше не читает этот сигнал, не содержит цикла по unit/deployment и не обращается к `GameState.getCampaignState()`/`replaceCampaignRoster()` на этом пути — он вызывает одну lifecycle-функцию и ставит runtime. Персистится **pre-action** `runtime.state` (подтверждённая игроком расстановка) до установки боевого runtime, поэтому throw оставляет фазу, runtime и roster нетронутыми. Контракт закреплён тестами: `tests/core/playerUnitPersistence.test.ts` (правило преобразования), `tests/core/battleLifecyclePhaseAction.test.ts` (маршрутизация: debug пишет только в debug, campaign только в campaign, отклонённый begin-combat не пишет никуда), `tests/battle/combatStart.test.ts` (сигнал). **Не достигнуто и не входило в стадию:** exit-персистентность (HP/life-state/level/placement) остаётся route-specific и campaign-only до Stage 7; `applyBattleExitPlayerPersistence` продолжает писать `lastPlacement` своим правилом и молча пропускает неизвестные templateId — две политики ошибок в одном файле сводятся в едином exit-стадии; lifecycle debug-сессии не менялся: `init_debug` по-прежнему пересоздаёт сессию, поэтому debug-placement живёт только внутри текущей debug-сессии. |
